# Review — full repository, at v0.1.0+11  (2026-07-28)

A code-level review of the whole repository at `bb63e12`: the query engine,
the schema pipeline (`schema`, `migrate`, `introspect`, `shadow`), the HTTP
and codegen layers (`filter`, `rest`, `codegen`), and project health (docs,
ADRs, examples, CI). Four independent passes, one per area; every finding
below was verified against the source, and the two high-severity ones were
re-verified by hand before being written down.

This review deliberately does not re-argue what the repository's own reviews
already settled. [review-adoption-readiness.md](review-adoption-readiness.md)'s
six findings are all verifiably closed. [FEEDBACK.md](../FEEDBACK.md)'s three
build reports are dated today and their items are essentially all still open;
where a finding here overlaps one of theirs, it says so rather than claiming
novelty.

## Verdict

**The design is sound, the discipline is real, and the remaining defects are
concentrated exactly where the project's own tests are thinnest: the mutation
write-back path, the default error path, and the edges of adoption.** No
injection path was found anywhere — identifiers resolve against the model
before reaching SQL, values are always bind parameters, and the escape
hatches say so. The CI gate is top-percentile: real Postgres 18, PgBouncer in
transaction pooling, generated-code drift checks, `tsc` over the emitted
client, per-commit bisect.

Two new findings are serious enough to fix before inviting consumers: a
row-misalignment bug in `Insert.Exec` under `ON CONFLICT DO NOTHING`, and
500 bodies that carry compiled SQL and constraint names to HTTP clients.
The second converges with FEEDBACK's #1 finding (typed constraint errors):
one piece of work — classify class-23 errors, sanitize the default 500 —
closes both, plus the enum-validation gap below. That convergence makes it
the single highest-leverage change in this document.

## What holds up

Stated to calibrate the findings, not as praise.

- **Bind discipline is airtight.** No value path reaches SQL text;
  `LIMIT`/`OFFSET` are validated integers; identifier quoting is proven to
  neutralise injection by test. Hidden columns are probe-resistant: a hidden
  column and a nonexistent one produce the same rejection.
- **Keyset pagination is the most careful in any Go builder reviewed.**
  NULL placement relative to direction, nullable columns disqualifying the
  row-constructor fast path, cursor-vs-ordering validation with a
  400-mappable sentinel, decode into the column's Go type — all handled and
  round-trip tested rather than golden-string tested.
- **The transaction story is complete and tested**: panic-safe rollback,
  nested-join semantics, isolation narrowing refused, `AfterCommit` drained
  on the outer context so callbacks cannot find a dead transaction.
- **`migrate.Diff` safety design**: destructive changes render commented out
  with reasons and take their dependents with them; lock hazards are
  classified per statement with generated `Unblock` sequences; renames are
  declared, not inferred. All of it pinned by tests, including positive
  controls proving the guards can fire.
- **Codegen is deterministic and gated.** Sorted keys, gofmt at generation
  time, `codegen.Check` in CI over every artifact, and the example apps
  compile the output.
- **Docs match code.** Guide snippets are compiled `Example` functions;
  spot-checked signatures all current. The ADR convention (living documents,
  Status/Confidence split, "what would change our mind") is executed, not
  just declared.

## Findings

Ordered by what to fix first, not by package.

### 1. `Insert.Exec` writes returned rows back by position; `ON CONFLICT DO NOTHING` misaligns them — HIGH

[mutate.go:219](../mutate.go). The write-back loop maps `RETURNING` rows to
input rows positionally: `*i.rows[n] = stored[n]`. `OnConflictDoNothing` is
documented as making skipped rows "simply absent from the result" — so
insert A, B, C where A conflicts, and `stored` is `[B', C']`: B's stored
values, **including B's generated primary key**, are written into the
caller's struct for A, and C's into B. The caller now holds structs claiming
identities they do not have, and anything keyed off them afterward corrupts
data. The seeding idiom FEEDBACK report 2 praised — `OnConflictDoNothing`
for idempotent inserts — is exactly the path that hits this.

**Fix.** When a do-nothing conflict clause is set and
`len(stored) != len(i.rows)`, skip the write-back (and document that skipped
rows are not updated), or match returned rows to inputs by the conflict
target columns. Add the missing test: multi-row insert with one skipped row.

### 2. Unclassified database errors leak SQL text and constraint names to HTTP clients — HIGH

[exec.go:311](../exec.go) wraps driver errors with up to 400 characters of
the compiled statement; [rest/errors.go:131](../../rest/errors.go) returns
anything it cannot classify raw, and Huma places `err.Error()` in the 500
body. This is user-triggerable, not an outage path: POST a duplicate unique
value — or an invalid enum value (finding 5) — and the client receives the
INSERT text plus the raw Postgres error naming table, column, and
constraint. The package comment frames "text left to Huma" as deliberate;
schema disclosure through a public endpoint is the unacknowledged
consequence.

**Fix — and it is the same work as FEEDBACK finding 1.** In `asHumaError`'s
default branch, log server-side and return a generic 500. Then classify
class-23 SQLSTATEs: the dependency-free `errors.As` against a local
`interface{ SQLState() string }` yields the class (pgx implements it), which
is enough for `rest` to answer 409/422; a pluggable classifier
(`sqlb.SetErrorClassifier`) carries the constraint name for applications.
FEEDBACK report 3 already reduced this to "a translation to perform" and
scoped the design, including emitting `XxxIndexes.Name` constants from
codegen so a constraint rename becomes a compile error. One change closes:
the information leak, the 500-for-client-mistake gap every application hits
on day one, and the fragile `strings.Contains` matching both examples do.

### 3. Expansion reads the target model without the target's `BeforeQuery` hooks — needs a decision

[expand.go:115](../../expand.go) (forward join),
[expand.go:217](../../expand.go) (collection subquery). Hooks are the
documented tenancy mechanism — "a single registration applies a constraint
to every read of that model" — but `Expand` joins or subqueries the target
table with only the FK correlation; the target's registered `BeforeQuery`
predicates are never consulted, and `rest` exposes `?expand` to clients.
The mitigating fact: expanded rows are only those the scoped parent's FK
references, so leaking requires a cross-tenant FK reference — which
composite-FK confinement is designed to prevent. But the guarantee currently
rests on the schema being right, not on the hook the docs say is the
mechanism, and nothing documents that.

**Fix.** Decide and state the contract. Either compile the target's
registered predicates into the join/subquery, or refuse expansion when the
target has `BeforeQuery` hooks (with an explicit opt-out), or document
prominently in `hooks.go` and the REST guide that expansion trusts FK
confinement rather than hooks. Silence is the only wrong option.

### 4. The filter grammar's budgets have two bypasses — MEDIUM

The `MaxFilters` budget counts entries in `q.Where`, but:

- an `in`/`nin` list is one entry with unbounded members
  ([filter/filter.go:406](../../filter/filter.go)) — tens of thousands of
  bind parameters from one query param, failing at the driver's 65,535 limit
  into finding 2's leaky 500;
- an `or=`/`and=` group is one entry with capped depth but unbounded width
  ([filter/filter.go:469](../../filter/filter.go)).

Related, lower: `like`/`ilike` patterns and `?search=` terms have no length
cap, so pathological patterns (`%a%a%a%…`) are a cheap scan-cost lever on
any filterable text column.

**Fix.** Cap list membership and count group leaves against `maxFilters()`;
cap value/term length; report violations like the existing limits. Add a
`FuzzParse` — the designated untrusted-input parser currently has no fuzz
test.

### 5. Generated create/patch bodies do not validate enum values server-side — MEDIUM

[codegen/rest.go:99](../../codegen/rest.go) emits enum columns as plain
string aliases, so Huma's schema says `"type": "string"` and `{"status":
"bogus"}` passes 422 validation, reaches the INSERT, and returns as finding
2's 500. The TS client and the CLI both enforce the value set; the server —
the one that must — is the weakest link. Huma supports an `enum` struct tag.

**Fix.** Emit `enum:"…"` tags in `renderCreateBody`/`renderUpdateBody`; the
value set then validates at 422 and lands in the OpenAPI document for free.

### 6. Mutation statements are not cloned before hooks, unlike queries — MEDIUM

[mutate.go:347](../../mutate.go), [mutate.go:444](../../mutate.go).
`Builder.All` clones precisely so hooks do not accumulate across
re-execution, and a test pins it. `Update.Exec`/`Delete.Exec` run hooks
against the statement itself: a `BeforeUpdate` doing
`u.Set("updated_at", now)` — the doc comment's own example — appends a
second assignment on re-exec, and a scoping `Where` narrows twice.

**Fix.** Clone `Update`/`Delete` before running hooks, matching the query
path, or document mutation statements as single-shot. The asymmetry is the
bug either way.

### 7. `Count` silently drops `DISTINCT` — MEDIUM

[builder.go:400](../../builder.go). `Distinct()` queries get
`SELECT count(*)` over the undistinct set, so `?count=exact` disagrees with
the rows returned. The grouped case already wraps in a subselect; the
distinct case needs the same treatment and a test.

### 8. Introspection fails on common real-world databases — MEDIUM

Two edges, both on the adoption path the README advertises:

- **Self-referential FKs drop the whole column.**
  [introspect/build.go:345](../../introspect/build.go) resolves FK targets
  against a map populated only after the table is built, so
  `employees.manager_id → employees.id` skips the *column* (not just the
  constraint), with a report claiming the table "is not in the schema being
  read" — false, it is the table being read. A registry missing a real
  column turns `Diff` destructive.
- **Any mixed-case identifier aborts the whole import.**
  [introspect/build.go:43](../../introspect/build.go) runs the built
  registry through `Validate`, whose `isIdent` rejects uppercase — so one
  camelCase column (routine in Rails/Prisma databases) fails the entire
  import with an error framed as an internal bug, instead of the
  partial-registry-plus-Report the package's own doc promises.

**Fix.** Import an unrepresentable-FK column as a plain typed column and
report only the constraint; special-case the self-reference message.
Pre-screen names in `build` and report them as unrepresentable rather than
letting `Validate` abort.

### 9. Diff churn: partial-index predicates and 63-byte identifier truncation — MEDIUM

- [migrate/ddl.go:735](../../migrate/ddl.go) compares index `Where` text
  verbatim; introspection returns Postgres's normalized form. A partial
  index therefore never byte-matches, and every diff against an introspected
  or shadow state proposes `DROP` + `CREATE INDEX CONCURRENTLY` — a full
  rebuild per cycle, forever. The analogous check-constraint churn is known
  and logged in the round-trip test; the index case is worse and untested
  (the round-trip schema contains no partial index).
- Generated index/constraint names
  ([schema/table.go:284](../../schema/table.go)) are never checked against
  Postgres's 63-byte limit; Postgres silently truncates, and every
  subsequent diff proposes a rename that truncates back.

**Fix.** Add a partial index to the round-trip schema so the gap is
measured, then treat a same-name index differing only in `Where` text as
suspect-with-comment rather than rebuild. Check generated names in
`Registry.Validate` with an `AddIndex(schema.Index{Name: …})` suggestion —
consistent with fail-at-generation.

### 10. Shadow replay and formats: `CONCURRENTLY` outside goose — MEDIUM

[shadow/parse.go:53](../../shadow/parse.go) honors `NO TRANSACTION` only for
goose; every other format's statements run inside one explicit transaction —
so `shadow.Build` cannot replay the golang-migrate output `migrate.Unblock`
itself generates (`CREATE INDEX CONCURRENTLY` errors in a transaction
block). Upstream, the golang-migrate format emits multi-statement concurrent
files that fail at that runner too. Lower, same package: the statement
scanner does not handle `E''` escape strings —
[shadow/parse.go:243](../../shadow/parse.go) splits `E'it\'s…'` at the
escaped quote.

**Fix.** Detect `CONCURRENTLY` per statement in shadow and run it outside
the transaction; either document the golang-migrate limitation or emit one
concurrent statement per file for that format. Teach the scanner the `E`
prefix.

### 11. `docs/architecture.md` contradicts the newest shipped feature — MEDIUM

The flagship doc's diagram says the TypeScript client is "not built" and
generated from `openapi.json` — ADR-0028 shipped it and argues at length why
it *cannot* come from OpenAPI. "Known gaps" still lists it; the package
table omits the TS/CLI emitters and `shadow`; *Last reviewed* predates
ADRs 0028/0029. By the repo's own rule — stale documents are worse than
absent ones — this is the highest-priority doc fix.

### 12. Still open from FEEDBACK.md, endorsed here — MEDIUM unless noted

Verified still open at this HEAD; the build reports' arguments stand and are
not repeated:

- **`schema.SoftDelete()` + `Expose(OpDelete)` compiles and hard-deletes** —
  the one place the library silently does the opposite of what the schema
  declares. Make it a registration error. (Report 3's view-based design is
  worth weighing before shipping the hook-pair helper.)
- **Row locking and the `AfterCreate` FK-lock deadlock are undocumented.**
  `ForUpdate`/`SkipLocked` appear nowhere in `docs/`; the guaranteed
  deadlock (FK key-share on insert, then `FOR UPDATE` upgrade in the hook)
  costs one paragraph and saves a post-deployment day.
- **The "what fires when, inside which transaction" page** — asked for by
  two reports; every answer currently lives in the source.
- **Codegen omits setters for `ReadOnly`/`Immutable` columns**
  ([codegen/columns.go:80](../../codegen/columns.go)) — so the trusted code
  that exclusively writes those columns is the only code without the typed
  API.
- Low: lint's `unindexed-filter` message names a capability the column lacks
  ([schema/lint.go:94](../../schema/lint.go)); the `Coalesce(Sum(f).Expr(),
  …)` idiom appears in no example; no arithmetic upsert; `.Optional()`
  discoverability; the two proposed lint rules (Unique + non-null Default;
  ReadOnly + Default + OpCreate).

Since fixed (do not re-fix): report 1's "cursor paging reachable only
through rest" — `Builder.After`/`CursorFor` landed with ADR-0027.

### 13. Smaller confirmed items — LOW

- [filter/filter.go:62](../../filter/filter.go): doc comment still claims
  `rest` rejects a non-empty `Expandable`; it now implements it.
- [rest/list.go:119](../../rest/list.go): unknown `?count=` values are
  silently ignored, against the packages' "refused, never ignored" stance;
  `isnull`/`notnull` are accepted on non-nullable columns while documented
  only for nullable ones.
- TS client types `bigint` as `number` —
  [codegen/tsclient.go:626](../../codegen/tsclient.go); precision silently
  lost above 2^53. Document at minimum; a string-serialization option is the
  real fix.
- [expand.go:193](../../expand.go): the `json_build_object` key splices the
  column name into a string literal unescaped — developer-controlled, but
  the only unquoted name path in the package. Escape or validate at model
  build.
- `Call.Name` ([compile.go:191](../../compile.go)) is verbatim SQL with no
  doc warning, unlike `Raw` and `Cast` which both carry one.
- `Insert.Only`/`Omit` accept unknown column names silently, while `Set`
  validates; a typo inserts nothing, quietly.
- Collection `order=` tags are unvalidated until the database rejects them
  ([relation.go:103](../../relation.go)) — contrary to fail-at-build.
- `Update.One` reports "expected one" only after updating every match;
  outside a transaction the extras are already durable. Document, or
  compile a guard.
- No `CONTRIBUTING.md`, `SECURITY.md`, or release-notes vehicle —
  [compatibility.md](compatibility.md) promises release notes that have
  nowhere to live. The gap between "tagged" and "adoptable by a stranger."
- [compatibility.md:53](compatibility.md) points at a README section that no
  longer exists; [example/tasks/README.md:36](../../example/tasks/README.md)
  has an unquoted `&` in its curl example.

## Test gaps, consolidated

Coverage is strong where the design is strong. The gaps track the findings:
no multi-row insert test with a conflict-skipped row (1); no test pins the
body of an unclassified 500 or drives a unique violation through POST (2);
no expansion test with a hook-guarded or schema-qualified target (3, and the
one-line `c.ident` vs `c.table` bug at [expand.go:134](../../expand.go));
no huge-IN-list or wide-group test (4); no `Distinct().Count()` test (7);
no round-trip partial index (9); no fuzz test for `filter.Parse`; and the
fake driver discards bind args on exec, so no unit test can catch an
arg-ordering bug at the driver boundary.

## Recommended sequence

1. **Finding 1** — data corruption, small fix, missing test. First.
2. **Finding 2 + FEEDBACK #1 as one change** — sanitize the default 500,
   classify class-23, pluggable classifier, index-name constants from
   codegen. Closes findings 2 and 5's blast radius and the top item of all
   three build reports at once.
3. **Findings 4–7** — filter budgets, enum tags, mutation clone, distinct
   count. Each small, each with a test.
4. **Finding 3** — decide the expansion/hooks contract and write it down.
5. **Findings 8–10** — the adoption edges, before advertising the
   introspect/adopt path harder than today.
6. **Docs batch** — architecture.md, locking + deadlock paragraph, hook
   firing matrix, SoftDelete registration error, ReadOnly setters,
   CONTRIBUTING + release notes.

None of this changes the prior review's closing judgement: the design is not
what is holding the project back, and elapsed time under someone else's
traffic still cannot be manufactured. But findings 1 and 2 are the kind that
spend adopter trust faster than time can earn it — they are what "while that
time passes" is for.
